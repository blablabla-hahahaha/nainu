# Agent Note: 回放控制条——播放组常驻、操作组固定右侧、调试记录入口

Status: implemented

## Problem

回放控制条（`web/src/components/workflow/replay/replay-controls.tsx`、`use-replay-state.ts`、`workflow-page.tsx`）此前把播放组隐藏到「存在执行记录」才显示：未执行时整组消失，居左的操作组因失去左侧进度条的顶推而整体左移；执行状态 `Tag` 常驻展示 `idle` 等状态；「调试结果」入口混在播放组里，与其「打开记录面板」的功能不符，且面板关闭后缺乏稳定再入口。

## Decision

- **播放组常驻显示**：移除「无执行记录就整组隐藏」的门控，播放/步进/倍速/进度条/进度计数始终展示；按钮沿用既有 disabled 语义灰显（播放按 `!runId`，步进/倍速/进度条按 `!is_replay`），未执行时整组灰显，只表达「尚无内容可播放」。
- **操作组固定右侧**：进度条以 `flex:1` 顶推操作组（运行/暂停/恢复/调试记录）至控制条最右，不再因播放组消失而左移；操作组与播放组以垂直分隔线相隔，分隔线仅在有播放组（即已有执行记录或恒常展示情形）时呈现。
- **移除状态 `Tag`**：从控制条删去执行状态 `Tag`（`idle/running/completed/failed/paused/回放`）及 `execution_tag_color`；执行状态改由按钮态（`loading`/禁用）与节点可视状态承载，播放组回归纯播放职责。
- **「调试记录」入口归入操作组最右**：按钮由「调试结果」更名为「调试记录」，置于操作组末位；`disabled={!has_runs || log_open}`——无执行记录或面板已打开时置灰，避免语义误解。点击由页面触发 `set_show_event_log(true)` 并 `load_replay(runs[0].runId)`（`runs` 新→旧，`runs[0]` 即最近一次执行），默认选中最近一次记录并回放到其完成态。
- **关闭面板重置回初始**：新增 `reset_to_init()`，关闭调试记录卡时调用——关闭事件源与计时器、`runId=undefined`、`mode='live'`、`events=[]`、`position=0`、`playing=false`、执行状态回 `idle`、`dispatch(runtime/reset)`；保留执行历史 `runs`，使播放组与「调试记录」入口在关闭后仍可用。

## Alternatives considered

**未执行时隐藏播放组、仅留操作组（前版/现状）**：界面更克制，但操作组会因失去进度条顶推而左移，播放能力也完全不可见；未采纳，改为常驻 + 灰显。

**关闭面板时连执行历史一并清空（彻底 init）**：更贴合「恢复初始」的字面语义，但会使播放组与「调试记录」入口一并消失，与「面板打开时置灰、关闭后可再点开」的补偿需求冲突；保留 `runs`，仅重置运行时/播放态。

**「调试结果」入口留在播放组（前版）**：与「打开记录面板」的职责不符，且会随面板开合影响入口可用性；移入操作组最右。

## Consequences

- 控制条布局稳定：播放组左侧常驻、操作组右侧固定，不因执行与否或面板开合变化而漂移。
- 未执行时播放组整组灰显作占位，避免「误以为可播放」的语义误解；有执行记录后自动恢复可用。
- 执行状态不再在控制条单独显示，改由按钮态与节点可视状态承载；面板打开时「调试记录」置灰，语义清晰。
- 关闭调试记录卡即回到初始画布态并退出播放，需再次查看时点「调试记录」默认载入最近一次执行。
