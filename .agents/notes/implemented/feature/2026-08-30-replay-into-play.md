# Agent Note: 回放并入播放——播放即自动进入回放，播完再次播放则从头

Status: implemented

## Problem

回放控制条（`web/src/components/workflow/replay/replay-controls.tsx`）把「回放」与「播放」拆成两个按钮：须先点「回放」加载事件历史切入回放模式，再点「播放」才开始播。语义有重叠——播放本就是回放的历史重放，独立的「回放」入口冗余且增加理解成本；且播放到末尾后即停（`setPlaying(false)`），停留在末尾，重新观看需手动从头。

## Decision

- **移除「回放」按钮**：其能力完全并入「播放」。播放按钮在有 `runId`（存在可回放的历史）时可用：点击「播放」若不在回放模式，自动 `load_replay()`（拉取该次执行事件历史、切 `mode='replay'`、复位到 0），成功后 `setPlaying(true)` 开始播；点击「暂停播放」则 `stop_play()`；再次点击恢复播放。
- **播放到末尾停在末帧**：回放计时器前进到事件总数时即 `setPlaying(false)`（`next = Math.min(p + 1, length)`，`next === length` 时停），**不自动循环**。当用户已播放完毕（`position >= length`）再次点「播放」时，先 `setPosition(0)` 再从新播放——「再点一次即从头」。
- **步进同理**：`step` 在已播放完毕（`position >= length`）时，先 `setPosition(0)` 复位，再按常规前进（`Math.min(p + 1, length)`）——「播放完毕后点步进也从头开始」。
- **倍速重标定**：`speed_options` 数值整体翻倍（`1x=2`、`2x=4`、`4x=8`）——新 1x = 旧 2x（默认）、新 2x = 旧 4x、新 4x = 旧 8x；默认 `speed=2`（新 1x，即旧 2x 速度）。计时器最小步进间隔由 250ms 降至 `MIN_PLAYBACK_INTERVAL=100ms`，保证各档实际递进（500/250/125ms）不因下限坍缩。
- `load_replay` 返回 `Promise<boolean>`（是否加载到事件，供播放判断是否可播）；`play` 改为 `Promise<void>`。
- 播放/步进/进度条在非回放模式下的可用性由 `mode==='replay'` 决定（进入回放后启用），语义不变。

## Alternatives considered

**保留「回放」、让「播放」仅在回放模式下工作（现状）**：信息更明确但按钮冗余，且用户须记住先回放再播放的次序；未采纳。

**播放结束自动循环（从末尾复位重放）**：省去手动再点，但用户澄清语义是「播完停下、再次点击播放才从头」，非自动循环；未采纳。

**进入回放直接用已累积的 `events`（不重新拉取）**：省一次网络请求，但 live 运行中切回放时历史可能不全，且与 `fetch_events` 的服务端权威语义不一致；采用 `load_replay` 拉取。

## Consequences

- 控制条少一个按钮，播放成为回放唯一入口；点击播放即自动进入回放，从当前位置或从头播放事件轨迹。
- 播放到末尾后停在末帧；用户再次点「播放」即从头重放（暂停后再次点则从暂停处继续）。
- 播放完毕后点「步进」同样从头复位重步进；默认倍速为新 1x（=旧 2x 速度），档位按 1x/2x/4x 重标定为旧 2x/4x/8x，且各档实际速度递进（500/250/125ms）。
- 步骤/进度条在点击播放进入回放后启用，语义与原「回放/播放」一致；live（实时跟随）仍由「运行」驱动，互不干扰。
