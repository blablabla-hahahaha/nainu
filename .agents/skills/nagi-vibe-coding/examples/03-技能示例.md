# DeepSeek Harness 的 11 个技能（实例）

---

## 1. dsh-prose-standard —— 文风标准
> **何时用**：写/审/恢复/修剪/审计散文——含决定 Markdown、JSDoc、代码与测试注释、prompt、描述、诊断、CLI/UI 字符串里哪里需要文档/注释。
核心：写够以保存「契约」，再删推理过程、重复与装饰。它是「引导，不是脚本」。要求显式 `scope`；永远排除 `vendor/` 与冻结归档；按位置必需覆盖（公开 JSDoc / 内部注释 / 模块注释 / 测试 / 实操手册 / README / Agent Notes / 事故复盘 / 技能指令 / 提示词 / 诊断）。**保留完整命题**（主体动作/条件时序/情态/否定保证/所有权副作用/失败后果）。详见 `../references/02-文风与反泄漏.md`。
## 2. dsh-doc —— 文档工作流
> **何时用**：新建/重构/评审/审计/迁移 Markdown 文档、包 README 与文档网站。
工作流 8 步：读 AGENTS.md 与文档标准 → 分类页面（按一个主要职责 + 读者）→ 放到最近所有者 → 定义读者起点/结果/失败/恢复/下一步 → 写 YAML 元数据（`kind` 映射模板）+ Summary/TOC/用户内容/开发者内容/Further Exploration/Dev Note → 同遍更新双语对侧 → 核实每个声明并**实际运行页面教的命令** → 跑聚焦检查。**事实核查流程**：测试而非假设——只有「跑过它」才是操作声明的证据。
## 3. dsh-code-review —— PR 评审
> **何时用**：评审一个 PR——把评审者导向代码库标准与「仅靠代码无法展示」的评审专项检查。
定位：引导，不是完整清单。先抓 PR 实时 base + 精确 head、跑 `change-scope`，再读 diff。**正确性/生命周期/安全/被破坏必需行为优先于风格**；一个带实锤 blocker 的短评审好过一串 nit。阻塞项：新增散文语义评审、文档匹配代码、注册清理、不变式语义化、必需证据、客户端文案本地化。
## 4. dsh-pre-push-checks —— 推送前检查
> **何时用**：推送/强推/标记 ready/声称检查通过前，以及 `gh stack sync` 发布改写分支后立即——选覆盖 diff 的**最小**检查集。
核心：没有普遍本地基线。每个行为变更跑「最窄的、会在其回归上失败的」测试或专项检查。**不要**手动重复已通过的检查（尤其别为重复 pre-push 钩子跑 typecheck）。历史改写用 `--force-with-lease`，裸 `--force` 永不。
## 5. dsh-archive-agent-notes —— Agent Notes 归档
> **何时用**：新增/审计/修剪/归档/恢复/评审 Agent Notes。
语义判断，词数与年龄只是发现线索。新增 note 触发取代审计；implemented 按「未来决策价值」归档；proposed 永不归档；rejected 只作护栏保留。归档 = 移动完整三件套 + 不改正文 + 插入 `Archived:` 行 + 重录 sidecar + 修/删入站链接 + `verify-archived-agent-notes --write`。封存后永久冻结。
## 6. dsh-find-simplifications —— 找简化点
> **何时用**：找非显而易见的简化候选、删冗余注释/实现过重文档、写 proposed note 或内联 TODO、审计/合并被取代的 note。
强候选：无生产消费方的公开面；两处表示镜像同一事实；接缝有无人用的方法；投机性泛化；手搓重实现了维护良好的依赖。薄候选不够。证明/否决每个候选：先分类消费方、`rg` 先行、有生产调用方或被记录依据背书就否决。
## 7. dsh-merging-stacked-prs —— 落 stack PR
> **何时用**：落依赖 PR 栈（A ← B ← C）、合并以另一开放 PR 分支为 base 的 PR。要求用 GitHub 官方 stacked-PR 特性。
经 `gh stack merge` 落栈，不用 `gh pr merge` 逐个合并复刻栈语义。官方扩展不可用就硬停。
## 8. dsh-trim-cot-leakage —— 清除思维链泄漏
> **何时用**：审计/修复读起来像「泄漏推理过程」的散文（死设计会话引用、变更叙述、评审视角、控制流叙述、试探残留）。
一个测试：HEAD 读者能否解析每个引用、核实每个声明？8 类分类学 + 「什么不是泄漏」保留规则。详见 `../references/02-文风与反泄漏.md`。
## 9. dsh-translate-docs —— 双语文档翻译
> **调用边界**：只有用户显式点名才运行（`disable-model-invocation: true` + `user-invocable: true`）；日常翻译走一次通过规则。
按变更类型分诊：更新走简报驱动路径（`gen-translation-brief`，机械-only 可 `--apply`，散文 diff 委托子智能体）——**绝不整篇重译**；新对走整篇路径（编排者不译，spawn 子智能体译）。术语表是唯一权威，翻译前加载。
## 10. record-browser-gif —— 录浏览器 GIF
> **何时用**：把浏览器/Web UI 交互 demo 录成优化 GIF；**每个改变产品用户可见 GUI 行为的 PR 都必须附**从该 PR 真实服务器与模型流录制的 GIF。
录制与发布分离；真实服务器 + 真实 API + 真实模型轮，绝不用 fixture/mock（除非用户显式要求）；GIF 永不进 PR 自身分支，放专用孤儿 assets 分支。
## 11. （结构对照）技能目录还含
`dsh-doc/references/`（metadata-links-i18n / structure-hierarchy / style / review / website-sync）、`dsh-doc/templates/`（package-group / package-reference / package-library / package-bundle）、`dsh-prose-standard/references/examples.md`、`dsh-trim-cot-leakage/references/{examples,recall-batteries}.md`、`record-browser-gif/scripts/encode_gif.py`。

## 结构点评（生成时对照）
1. **11 个技能 = 5 个「写作/文档」类 + 3 个「工程流程」类 + 1 个「翻译」类 + 1 个「评审」类 + 1 个「录制」类**——覆盖了智能体在该仓库里反复出现的高价值任务。
2. 每个技能的 `description` 都精确到「何时用」，这是可发现性的关键。
3. 目标项目按自己的反复任务建技能，**起步 5 个即可**（见 `../references/07` §5）。
