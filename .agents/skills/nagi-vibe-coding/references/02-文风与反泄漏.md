# 文风标准 与 反「思维链泄漏」

---

## 第一部分：文风标准（dsh-prose-standard）
### 核心主张
**写够以保存「契约」，然后删掉推理过程、重复与装饰。** 契约是调用方、被调方、实现者、生产者或消费者所依赖的一项义务、不变量、前置/后置条件或兼容承诺。
> 本技能是「引导，不是脚本」。它拥有编辑判断与必需散文覆盖。
### 术语检查
把 `contract` / `boundary` / `shape` / `surface` / `seam` / `gate` / `vocabulary` 当「用前要检查」的词，不是禁用词。先问更精确的规则/API/字段集/类型/校验/时序点/组件拆分/失败状态是否表述得更好。当它精确命名技术主体时保留该词。
### 输入与排除
- 要求显式 `scope`；缺失就报告并停下，不推断全仓库范围。
- `mode: automatic | interactive`，默认 automatic；只有用户显式要求提问才 interactive。`mode` 控制提问，不控制写权限。
- 永远排除第三方 vendored 目录；也排除冻结的归档记录（只查历史入站引用，不现代化其散文）。
- 生成的目录、快照、fixture 视为派生物：先改归属源，再重新生成每个派生物。
### 保留完整命题
编辑前识别每处命题，保留每个相关的：**主体与动作；条件、时序与顺序；情态（must/may/never）；否定保证与异常；所有权、副作用、失败模式与后果**。只有当每个事实子句都存活、结果更清晰时才删形容词/重复/叙述。**更小的词数本身不是改进。**
### 按位置的必需覆盖（不是单向缩短——代码/类型/结构没表达下述契约时要补回）
| 位置 | 必需的散文 |
|---|---|
| 公开 JSDoc | 可区分的返回值、throw/reject、副作用、所有权、时序、取消、持久性 |
| 内部注释 | 非局部结构与显然复杂的局部结构（不变量、竞态顺序、所有权、安全边界、意外失败行为）；删控制流叙述与代码复述 |
| 模块注释 | 模块角色、依赖、职责、非显而易见架构选择（链接依据） |
| 测试 | 只解释非显而易见的测试设计（为什么需要某 fixture/断言/平台适配/真实入口/间接观察） |
| 实操手册 | 前置条件、必需动作、真实入口路径、可观察验证、简明警告 |
| README | 消费方契约：config、语义、失败、限制、扩展点、可见效应 |
| Agent Notes | 独有依据、机制、备选、后果、已交付验证证据、点名的覆盖缺口 |
| 事故复盘 | 事故序列、证据、因果链、影响、预防 |
| 技能与智能体指令 | 行为护栏 + 显式范围限制（如「引导，不是脚本/清单」） |
| 提示词与可见字符串 | 把措辞当行为 |
| 诊断 | 点名失败主体/路径、被违反的规则、纠正 |
### 工作流
1. 确认范围、模式、分支、适用的 `AGENTS.md`；
2. 读文档标准与归属代码后再判断一段话；
3. 检查请求的范围（不只最大的文件）；
4. 分类每个候选：keep / add / trim / restore / restructure / defer；只做授权过的清晰改动；
5. 先改所有者再改派生物；
6. 跑窄检查 + `git diff --check`；
7. 报告：检查过的范围、清晰改动、刻意保留、推迟项、实际跑过的检查。

## 第二部分：反「思维链泄漏」（dsh-trim-cot-leakage）
### 什么是思维链泄漏
读起来**视角是「写作会话」而非「仓库」**的散文：它引用只有那个会话看得到的产物、叙述「变更」而非「状态」、或与已离场的评审者争辩。修复**不是**光删——段落带事实子句时，先重述每个子句让它「站在 HEAD」，再删掉周围的 transcript；一个事实子句都没有的（审计码、控制流叙述）直接删。
### 一个测试
对每处可疑段落问：**一个在 HEAD、拿不到任何会话记录/PR 线程/未提交草稿的读者，能否解析每个引用、核实每个声明？** 不能 → 从仓库视角重述存活事实、删其余；能 → 不是泄漏（但可解析只过本关：在现状面上，可解析的变更故事仍是变更叙述，路由到其批准的家）。
### 八类分类学
1. **死设计会话引用**（`(decision 7)`、`(audit C2)`、`design §4.7`、阶段标签）——有提交所有者就按名+路径引用，否则删引用、重述事实子句；
2. **Stack/PR 视角**（"a later PR in this stack"、"this PR adds"）——陈述已交付机制或扩展点；
3. **变更叙述与版本戳**（"used to"、"no longer"、"the old X"、"v1"、"this cut"）——陈述现状；固定回归变现在时反事实（"without X, Y happens"）；
4. **评审编排**（"Rejected in review:"、"the reviewer confirmed"、草稿序号）——保留存活决策为平实事实；
5. **对评审者说的辩护**（"this is correct because…"）——陈述使代码安全的不变量；
6. **复述与推导记录**（控制流叙述、测试走查、证明显然分支）——删，只留非显而易见契约/不变量；
7. **试探与规划残留**（"probably fine for now"）——升为 `TODO`/`FIXME` 或重述为实际边界；
8. **作者语言滑移**（英文散文里的其它语言残片，或反之）——翻译或删除。
### 什么**不是**泄漏（保留规则）
- issue 引用（`#1470`、`TODO(name):`）在任何面保留；
- Agent Note 与 postmortem 里的 merged-PR/issue 引用是批准的证据；
- 压制理由（lint-disable 理由、覆盖忽略理由、空 catch 解释）是必需散文；
- 现在时反事实回归钉（"without X, Y happens"）；测量边界；运行时新旧状态；
- 按设计解析到仓库外的外部引用（RFC 章节、Figma 帧名）。

## 可迁移要点
1. 一句话：**写契约，删推理过程**。
2. 「保留完整命题」是编辑的底线——缩词不缩事实。
3. 「反泄漏」的**一个测试**（HEAD 读者能否解析每个引用）可直接用于任何代码库的评论/JSDoc/文档审查。
