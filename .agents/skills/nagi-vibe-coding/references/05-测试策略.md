# 测试策略

---

## 1. 分层（Tiers）
- **单元**：测试与它们锻炼的代码区同放（`tests/` 与源码同级）。每个注册表/插件都要有「释放安全」测试（dispose 贡献者，断言清理）。优先边界用例、错误路径、事件顺序、并发竞态、契约回归的永久测试。
- **覆盖率门禁**：**门禁运行**，源码每文件 100%（阈值自定）。一行未覆盖往往是该删除的死代码，不是要硬补的测试。**行覆盖必要但不充分**——它证明行跑了，不证明功能按交付方式工作。
- **真实 e2e**：带真实凭据测真实提供方/服务；每套件无凭据时自动跳过，让无凭据 CI 保持绿。自动跳过不是成本信号。
- **所有者本地预期输出**：免凭据的组装入口/进程预期，无录制往返。
- **快照/录制回放**：录制的输入提供「用户输入 + 模型/服务回放」，然后作为预期结果。CI 强制只读回放，绝不写预期输出；录制/刷新本地做、每次 diff 都要审查。
## 2. with-key / 真实环境策略：推理很便宜
「不要吝惜真实环境测试。」无凭据测试只证明管线通了；只有带凭据运行才证明系统对真实后端有效。最高价值是**冒烟测试**：启动一个交付入口、发一个最小请求、检查世界——它们抓「单元测试绿但产品坏」这一类 mock 抓不到的问题。自动跳过让无凭据 CI 不阻塞。
## 3. 优先真实实现，而非 mock
只 mock 昂贵或非确定性的边界（外部服务、网络、时钟）；下游一切保持真实。手工替身只证明「桥搬运了字节」，不证明交付组件按断言行为。桥接测试在脚本化 mock 边界后保留真实的下游。
恢复测试分离「边界前/后失败」，证明失败单元不派生消息或副作用。覆盖耗尽、取消、策略组合、持久化、状态、传输计数、关闭超时、交付组合。
## 4. 验证世界，而非自我报告
e2e 断言要**重跑命令或从外部重读文件**；对被测对象自身输出的关键词探测会让「作弊的实现」通过。断言未触碰文件逐字节相同。e2e 测试拥有自己的资源：测试里创建、`afterEach` 里释放（失败/重试/超时也如此）；共享 fixture 放独立 harness 文件，绝不从一个 spec 导入另一个 spec（会重注册 describe、重复真实调用）。
## 5. 测试真实入口路径
- 产品可见模块需要**非单元的真实组合测试**：手工装配的套件不够，要经真实加载器与应用/进程启动；只 mock 外部服务或非确定性输入，断言模型/用户/持久可见输出。
- 「真实入口路径」意味着**发布产物**：包 bin 在纯运行时下跑构建后产物，暴露开发态工具掩盖的失败（结算竞态、模块解析、被吞的加载失败）。
- 一个守卫只有「回归会让它失败」才算守卫；证明方式：引入回归、看红、回退。
## 6. 测试解析：仅源码平面
测试的模块解析指向源码，绝不经过包导出到构建后产物（那里的陈旧产物会加载第二份模块单例）。构建产物只被显式消费（构建冒烟、lib 模式子进程）。
## 7. 何时需要快照测试
每个非平凡的模型/协议/人类可见变更在同一 PR 新增或更新一份免凭据录制场景；包、e2e、mock-only、依据证据都不能替代组装后的 transcript。核心循环、生命周期、外部词汇变更更新所有下游投影。
---
## 可迁移要点
1. **每层断言自己的层**——数据层语义归运行时/宿主套件，组件测试只覆盖呈现行为。
2. **「验证世界，而非自我报告」**与**「测试真实入口路径」**是最通用的两条，任何项目照抄。
3. 「with-key/真实环境」与「录制快照」仅当目标项目有外部服务或 AI/agent 成分时保留，否则删。
