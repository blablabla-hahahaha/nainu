# 技能体系（skills）

---

## 1. 技能是什么
技能是**可复用的工作流与专项决策标准**，按需加载。智能体的技能目录会读出每个技能的 `description`，只有任务匹配时才加载该技能。
目录形态：
```
.agents/skills/
  <skill-a>/SKILL.md              # 主入口
  <skill-a>/references/<x>.md     # 按需加载的详细参考
  <skill-a>/templates/<x>.md      # 可套用的骨架
  <skill-b>/SKILL.md
```
## 2. SKILL.md 形态
```markdown
---
name: <my-skill>
description: <一句「何时用」——会被技能目录自动展示给智能体>
disable-model-invocation: false   # 可选：true 则禁止模型自动加载，只能用户显式点名
user-invocable: false             # 可选：true 则用户可显式调用
---
# <标题>
<一句话定位 + 本技能是「引导，不是脚本/清单」。>
## 真源（Sources of truth）
- <权威契约的链接>
## 工作流
1. <步骤>
## 验证
<归属验证命令>
```
## 3. 三条铁律
1. **技能是「引导（guidance），不是脚本 / 清单」**——几乎每个技能正文都明写这句话。机械的部分交给门禁脚本，技能只给判断框架。
2. **「工作流」与「权威契约」分离**——技能的权威内容链接回 docs（如文档结构/预算/模板的权威在 `docs/AGENTS.md`），技能自身只留流程。这样即使智能体不加载技能、直接在该目录下工作，也能通过子树指令读到权威。
3. **昂贵的、需人工把关的工作流锁定为用户显式调用**（`disable-model-invocation: true` + `user-invocable: true`），如「整篇翻译」。
## 4. `references/` 按需加载
每个引用从 SKILL.md **直接链接**，避免深引用链；智能体只加载任务需要的那个引用。
## 5. 目标项目要沉淀哪些技能
按「反复出现的、可流程化的」任务建技能，起步建议：
1. **文风标准**（写/审/修剪 prose）——照抄 `通用规范/02`；
2. **文档工作流**（放置、模板、审计、门禁）；
3. **代码评审**（把标准导向评审者 + 评审专项检查）；
4. **推送前检查**（选覆盖 diff 的最小检查集，而非全量）；
5. **决策记录归档**（Agent Notes 生命周期维护）。

## 可迁移要点
1. **frontmatter（name + description）** 是技能可被发现的关键——`description` 写「何时用」。
2. **权威在 docs，流程在 skills，机械检查在 scripts**——三者绝不互相替代。
3. 完整模板见 `../templates/SKILL.md模板.md`，DSH 的 11 个技能实例见 `../examples/03-技能示例.md`。
