# 防御性模式

做生命周期、并发、分布式锁、子进程或 teardown 工作前，先读本文件。七条规则与语言/框架无关，例子里换成本项目（Java 21 / Spring WebFlux / Redis）的等价场景。

## 1. 正交地报告独立结果

一个结果可能同时是几件事——一个 HTTP 调用可能「超时**并且**返回了部分字节」。每个独立事实（`timedOut`、`status`、`payload`）各自浮出；绝不把一个标志的报告嵌进另一个的分支里，否则调用方会把一次被截断的执行读成干净成功。

## 2. 在公开契约的**两侧**都履约

当实现收到同一结果的多种表示时，在经公开 API 返回前归一化它们。例（本项目）：Worker 执行结果可能以正常返回、超时、或 Redis 回调迟到三种形态到达 Master；Master 只把「节点完成」暴露为执行结果，中间件与消费方缺陷仍为异常。在类型定义处记录归一化契约；经真实消费方锻炼每种来源形态。

## 3. 异步状态不是同步状态

「发起一个异步操作」没有逐次完成/结果；后台任务的完成与主流程边界竞态（Master 的休眠/唤醒模型尤其如此）。**绝不**把某个状态事件当作某次操作的「结果」：多次排队、注入与取消可能共享一个「运行中」区间。真正拥有某次运行的一方必须显式定义其区间（如 `ctx:{instanceId}:lock`）。守卫是双刃的：若要等的转移永不发生，等待会挂起——**显式处理「无可等」分支**（如 Worker 未消费的任务）。

## 4. 释放必须到达完全停稳（quiescence），而非只是「请求」它

一个「发出取消却在工作停止前返回」的 teardown 会留下孤儿。把清理做成异步并等待子任务退出（cancel → await completion），并在取消**之前**关闭监听/订阅（Redis PubSub 订阅先退订，让迟到的完成保持沉默）。

## 5. 在分发器里收容回调异常

用户提供的监听器/回调 throw 时，绝不能拒绝它运行于其中的执行流、也不能饿死它后面的监听器。把分发循环包进 try/catch 并 log；一个坏订阅者永不破坏核心生命周期（`WorkflowExecutor` 的节点回调分发尤其如此）。

## 6. 绝不把不可信输出交给环境变量或可预测路径

被 spawn 的命令（Worker 的 JS/Python 沙箱）拿到**净化过的 env**（丢 `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`），使进程凭证不能漏进输出、env 或落盘文件。临时/溢出文件用私有目录、随机名、独占的所有者权限打开——可预测的世界可读路径等于邀请符号链接竞态与泄露。

## 7. 解除「链接形状」的路径

可能是指向符号链接的路径，先 `lstat` 判断再 `unlink` 移除：unlink 只删链接、拒绝真实目录，所以它绝不顺链接进目标。递归删除只留给已知真实目录。
